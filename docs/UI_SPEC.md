## 1. Visual direction
Dark "control room" theme: near-black panels, one dominant color + a single sharp accent (**default: signal orange** — defined as one CSS variable so switching to cyan is a one-line change; a timid, evenly-distributed palette is itself a slop signal — commit to the one accent, don't hedge with several). Monospace technical typography (JetBrains Mono / IBM Plex Mono), generous but non-uniform spacing (see §1d). All growth must be VISIBLE: rolling number animations, buttons that light up the frame they become affordable, progress bars everywhere a timer runs.

## 1d. Anti-slop rules (NEW — real player finding: the game was starting to read as generic/AI-made despite §1b's intent; researched current failure patterns and hardened the spec against them)
"AI slop" has a specific, well-documented visual signature that shows up regardless of a project's stated aesthetic unless explicitly blocked — negative constraints work where positive ones ("make it look good") don't, because the model is pattern-matching to a statistically safe average, not making a judgment call. Hard rules:
- **NO gray 1px border around every card/tile as the default separator** — this is the #1 slop tell. Default separation is whitespace first, then a 3–5% background-lightness shift for a panel that needs to read as distinct. A border is the LAST resort, only for genuine semantic state (e.g. a warning outline), never decorative, and never a flat gray line — use the accent or a state color with intent.
- **NO "Hero Metric" layout** (big number, small label underneath, colored accent dot or line on the left) as the default card shape — this exact pattern appears in the vast majority of generic AI-generated dashboards. Building tiles, the ticker, and the Site Map may NOT default to this shape; use the pictogram (§4) as the primary visual anchor instead of a decorative accent line.
- **NO gradient text, ever** — not on numbers, not on headings, not "for visual interest." Flat color only.
- **NO purple/blue/indigo as an accent** — signal orange is the one accent; this rule exists because indigo-on-dark is the single most common AI-slop tell, not because orange is inherently better.
- **NO three-identical-cards-in-a-row / bento-grid-by-default composition.** Where the game's own content genuinely repeats (building tiles, research nodes), that's fine — the rule targets composing a SCREEN that way by default when the content doesn't call for it (e.g. don't turn the v1 milestone screen or Settings into a bento grid just because that's the reflexive layout).
- **Spacing is disciplined, not uniform:** every spacing value is a multiple of 8px (4px as a half-step only) — but proximity must carry meaning (space inside a component < space between components < space between sections), and section padding should vary by weight, not repeat the same number everywhere. Uniform spacing everywhere is itself a tell (nothing has been decided to matter more than anything else).
- **Contrast target: APCA, not flat WCAG ratios** — target Lc ≥75 for body text, ≥45 for large/bold text, ≥30 for non-text UI (icons, borders). Verify before shipping any new screen.
- **A design-consistency check is part of "done":** before considering any new screen/component finished, ask "if I told someone AI made this, would they believe it immediately?" — if yes, it hasn't broken from the default pattern yet. Reuse exact tokens (the accent variable, the spacing scale, the type scale) from what's already shipped — do not invent a new one-off shade, spacing value, or shadow recipe per screen; that per-screen drift (no single owner of the visual system) is itself named as a root cause of slop in current design guidance.
- **Use the frontend-design skill's own anti-slop guidance directly** for any new UI work, in addition to the rules above — it exists specifically to counter this failure mode and should be consulted, not just this doc.
- **NEW (v3.9, real finding — screenshots after the Sprint 11.5 audit STILL read as slop despite passing that audit's checks): uniform card sizing regardless of importance is its own slop signature, independent of borders/gradients/hero-metrics.** Current-generation design guidance (2026) names this explicitly: "12 KPI cards that all look identical," "every card the same size regardless of content importance." Aurora Program's building-tile row (Offices/Finance/R&D Lab/Crew Quarters/Training Center, all identical size and structure) is exactly this pattern — technically compliant with every rule above and still reads as generic, because nothing on the screen tells the player what matters RIGHT NOW. **Fix: tie visual weight to the Current Directive (§2h).** The specific building the Directive is currently pointing at renders larger and with the accent-color border treatment; every other tile at that moment recedes to a smaller, quieter baseline size. This creates real hierarchy using a system that already exists (no new mechanic, pure presentation) and directly answers "cards sized proportional to importance" — the fix current design guidance actually recommends, rather than an arbitrary one-off resize. The same principle applies to research nodes once §5c's redesign ships: fork/mechanic-changing nodes render larger than percentage nodes, always, not just situationally.
- **The Sprint 11.5 anti-slop audit is CONFIRMED INSUFFICIENT** — it correctly checked for the rules that existed at the time (no borders, no hero-metric, etc.) and passed, but the uniform-sizing problem above wasn't in scope then and is real. Do not treat "passed the last audit" as "done" — re-audit against this section's addition specifically before Sprint 12.

**Before Sprint 12:** audit every screen shipped so far (Sprints 1 through 11) against this list specifically — bordered cards, hero-metric shapes, and per-screen style drift are likely already present since they were built before this section existed. Report findings, fix what's found.

## 1b. Achievable visual techniques (code IS the art)
North star: **SPACEPLAN** — a space incremental whose entire aesthetic is procedural SVG, proving code-only visuals can be beautiful. Techniques, in priority order:
1. **Blueprint aesthetic:** rockets and buildings drawn as geometric technical-schematic SVGs — thin lines, engineering-drawing style, stage annotations, dimension marks. Perfectly on-theme (real space programs look like this on paper) and fully code-generatable. Each rocket (S-1, S-2, Aurora I) gets its own blueprint that appears during assembly and on the launch screen.
2. **Technical typography:** a monospace font with tabular figures (JetBrains Mono or IBM Plex Mono via Google Fonts) for ALL numbers — tabular digits stop values "dancing" on every tick and instantly read as control-room.
3. **Animation layer (the real polish budget):** rolling numbers on change, single pulse when something becomes affordable, checkmarks that draw themselves (animated stroke), countdown digits with growing typographic weight. Pure CSS/JS.
4. **One particle moment:** canvas smoke/exhaust particles ONLY during countdown and liftoff — concentrate the special effect on the one moment that earns it.
5. **Subtle background texture:** a faint dark graph-paper grid via CSS pattern for control-room depth.
**Explicitly avoid:** AI-generated raster art (asset inconsistency is the #1 cheapness tell), character illustration, anything 3D, gradient/glow abuse. Coherent restraint beats inconsistent ambition — Universal Paperclips is pure text and iconic.

## 1c. Achievable audio techniques (code IS the sound — same philosophy as §1b, applied to audio)
**v1 sound is synthesized, not sourced.** All sound effects are generated via the Web Audio API (oscillator nodes — simple tones/chimes/beeps), never real audio files (.mp3/.wav/.ogg). Rationale, mirroring §1b's reasoning exactly: zero asset files means zero licensing questions and nothing for an assistant to fetch from the internet without explicit direction; trivially gated behind the existing (currently dead) Sound toggle in Settings; and "minimal" retro tones fit the control-room aesthetic better than mismatched stock sound effects would. Two required cues for Sprint 11: a tick/beep on each countdown second, and a distinct success chime on a successful launch result. Real produced audio is a possible post-v1 upgrade (BACKLOG), not a v1 gap.

## 2. Layout skeleton
- **Top ticker (persistent):** Funding, Materials, Hardware, Propellant — value + rate each; capped resources show value/cap and turn amber at ≥90%. **Above cap (one-time payment overflow, GDD §1c): value renders in the accent color with the cap dimmed and a "production paused" microcopy on tap.** Research, Reputation and Flight XP display in a secondary compact row (they update rarely). Hardware shows total; tier breakdown (Al/Ti) on tap once Titanium is researched.
- **Complex tabs (main nav):** Campus · Production · Testing · Launch. Locked tabs greyed with lock icon + unlock condition on tap. On desktop: left sidebar; on mobile: horizontal scrollable tab bar.
- **Building tiles** inside each tab: icon, name, level, production/effect line, upgrade button with cost (disabled+dimmed when unaffordable), progress bar when a process runs, staff slot indicator (2/2 dots). Locked buildings: dashed border + condition. **Building pictograms (Visual Identity 2.0 — the icon slot was a placeholder before, now a real rule):** every building gets a small blueprint-style line-icon (single stroke weight, single accent color, no fill except the accent) representing what it does — a technical schematic mark, not an illustration. One consistent icon per building, reused everywhere that building appears (tile, Site Map, upgrade lists, tooltips). Suggested marks: Offices (handshake), Finance (bar chart), R&D Lab (flask), Crew Quarters (bunk outline), Training Center (star), Supply Depot (crate), Fabrication (gear), Refinery (droplet+flame), Warehouse (stacked boxes), Propellant Depot (tank), Engine Test Stand (nozzle+flame), Launch Rail (rail track), Payload Processing (satellite dish), VAB (gantry crane), Launch Pad (tower), Launch Control (antenna), Tracking Station (dish), Launch Pad B (second tower, mirrored). Exact glyphs are Claude Code's call within the blueprint style — the CONSISTENCY rule (one mark per building, reused everywhere) is what matters, not the specific shape.
- **Mission Log:** collapsible bottom panel, last entry always visible as one italic line; expands to scrollable feed. Records board lives as a tab inside this panel.
- **Pending event card:** slides in bottom-right (desktop) / bottom sheet (mobile); two option buttons; never blocks input.

## 2b. Progressive disclosure (what the player can SEE, era by era)
Default rule: **hidden until relevant** — the player never opens the game onto the full content surface. Anticipation is created by a few *deliberate* teasers, not by showing everything greyed out.
- **Complex tabs:** all four visible from the start, locked ones greyed with their unlock condition — this is the intentional "there's more coming" signal, and it's the ONLY place the full breadth is hinted at.
- **Building tiles:** hidden until their complex unlocks. Within an unlocked complex, a tile appears only once its own unlock condition is met, with one designated exception: buildings marked `teaser: true` render locked-with-condition early. v1 teasers: **Training Center only** (the era-2 tease). Payload Processing and Launch Pad B stay completely hidden until Aurora I success — their appearance IS the post-climax "the program is growing" beat.
- **Research nodes:** a node renders only if it's available (deps met) or exactly one prerequisite away. Deeper nodes are fully hidden — the tree reveals itself one ring at a time, Kittens-style. Branch column headers are always visible (the four disciplines are known; their contents are not).
- **Ticker:** starts with Funding only; each resource row appears the first time the player gains (or can produce) that resource. The full 7-resource ticker is itself a progression artifact.
- **Manual verbs:** evolved verbs (Funding Rounds, Rush Order) appear only at their unlock; before that, no greyed button.
- **Records board:** earned records show fully; unearned ones render as dimmed unnamed placeholders ("———") — countable, not readable. Cheap anticipation without spoiling the arc.
- **Contracts panel:** does not exist in the UI until the Launch Rail is built.

## 2c. Active process strip (every timer is always trackable)
Directly under the ticker, a persistent horizontal strip lists **every** running process — research, certification, integration, transfer, training/promotion, contract build, weather window — as compact chips: `[icon] Label · 12m 04s` with a thin progress fill. Rules:
- **No process may exist without a chip.** Building-tile progress bars remain, but they are a convenience duplicate, never the only tracker: processes not tied to a visible tile (promotions above all) would otherwise be invisible, which is the bug this section exists to prevent.
- Tapping a chip jumps to the relevant panel/tile.
- Empty state: the strip collapses to zero height (no "nothing running" row).
- Chips complete with a brief flash, then the result lands in the Mission Log where applicable.
- Sorted by remaining time ascending (next completion first). Beyond 4 concurrent, overflow collapses into a "+N" chip that expands on tap.

**Staff availability everywhere:** every complex tab shows a compact staff chip in its header — `Available: 2 Tech · 1 Eng` (unassigned pool only) — so assignment decisions never require navigating to Campus first. Tapping it opens the staff panel.

## 2f. Mission Log visibility & generic process completions
Two real gaps: the Log lives collapsed at the bottom and is easy to never check, and several process types (promotions above all) completed with NO log entry at all — only mission/certification/building beats had narrative IDs.
- **Unread badge:** the collapsed Log header shows a small count badge the instant a new entry lands, clearing when the player opens the Log.
- **Every completed timed process gets a log line**, not just the ones with full narrative beats. Generic completions (promotions, research nodes, upgrades) get short functional lines (NARRATIVE §9 gains entries for these) rather than the flavor-heavy Mission Log prose — same panel, different register, both routed through the same unread-badge mechanism.
- **Category icon badges (Visual Identity 2.0, cheap win):** each log line gets a small icon by category (rocket = launch/mission, flask = research, people = staff/promotion, building = construction/upgrade, document = contract, star = record) so the feed scans visually instead of reading as a uniform wall of text.

## 2g. Research moves to its own tab (structural change)
Research is not thematically owned by any one complex — it feeds all of them. **Promote it from "a panel inside Campus" to a 5th top-level tab**, sibling to Campus/Production/Testing/Launch, with the same unlock condition (appears once R&D Lab is built) and lock treatment (greyed with condition before that). Redesigned layout: see §3's Research screen entry below (two designs considered, one selected).

## 2h. Current Directive (persistent "what now" indicator)
Real gap found across repeated owner playtesting: confusion recurred at multiple unrelated moments (why launch this sonda, what does this building do, what's next) — a symptom with one root cause, not many separate ones. Fix: a short, dynamic line of text, always visible near the ticker, stating the single most relevant next step given current game state — "Build Finance to keep growing your funds" → "Assign your first Technician" → "Research Sounding rockets" → etc. Extends the existing FTUE tooltip system (NARRATIVE §2) into an ongoing feature rather than a one-time onboarding pass; a small table of key-milestone directives lives in NARRATIVE (new entries, referenced by ID) — Claude Code may extend the pattern to additional states as needed, following the same terse, action-first phrasing. Updates automatically as state changes; no dismiss button, it just changes.

**Program Site Map (Visual Identity 2.0 — THIRD reconception, v3.9. Real finding: the second rework was implemented as specified (own destination, celebration moment) and STILL reads as "purely aesthetic, poorly designed, no impact" — owner screenshots confirmed a small modal of outlined icon boxes, closer to a debug overlay than blueprint art. Root cause identified this time, not just symptom: the map has never carried information the Campus/Production tabs don't already show — "which buildings I've built" is redundant, so no amount of styling can make it feel meaningful. This rework changes what it's FOR, not just how it looks.):**
- **Real information the tabs can't give: live, whole-program activity at a glance.** Every building's pictogram on the map pulses/glows proportional to its CURRENT production rate (or shows a paused/starved indicator matching its tile's own state) — something no single tab can show, since each tab is scoped to one complex. This is the actual "how alive is my program right now" view — genuinely new information, not a re-listing of what's already built.
- **The map IS the Current Directive's canvas, not just its neighbor.** Whatever building the Directive currently names is highlighted directly on the map (the same visual-weight treatment as §1d's new importance rule) — "go build Finance" comes with a literal spatial pointer, giving the map real navigational utility instead of being a passive backdrop.
- **The celebration moment on new buildings stays** (from the second rework) — it was correctly implemented and is not the problem; keep it.
- **Entry point:** same as before — own icon near the ticker, opens the full map. Layout: schematic top-down, four complexes in fixed relative positions, pictograms per §4, empty plots as dashed outlines.
- **If this third attempt still doesn't land:** the next step is not a fourth visual rework — it's asking whether "Program Site Map" should exist as a standalone destination at all, versus folding its one genuinely valuable piece (the celebration moment) directly into the Current Directive area and retiring the rest. Flag that question rather than attempting a fourth cosmetic pass.

## 2i. Constellation View (Visual Identity 2.0 — new)
A live, growing visual of every successful orbital mission: a central circle (Earth) with one small dot per successful satellite — Aurora I, Aurora II, every fulfilled satellite contract — placed on a simple orbital ring (a second, slightly larger ring for later/higher missions if visual distinction is wanted, but one ring is a fine v1 default). Dots accumulate permanently and never disappear; tapping one shows which mission it was and when. This is the "look what you built" payoff screen — accessible from the Tracking Station building tile (thematically: the Tracking Station is what watches your satellites) and, once it has ≥1 dot, from a small persistent icon+count near the ticker (tap to open the full view). Depends on satellites existing — natural home is after Sprint 10 (Aurora II) so the view launches already showing real variety instead of one lonely dot.

## 3. Screens
1. **Main dashboard** — ticker + tabs + tiles (above).
2. **Staff panel** (from Campus tab or ticker tap): role pools, hire buttons with next cost, assignment matrix (building × role steppers), salary total/s vs income/s, capacity bar (Quarters). **Role silhouette icons (Visual Identity 2.0, cheap win):** each role gets a small abstract geometric silhouette (a generic outline figure, no facial features, distinguished only by a role-colored accent mark — e.g. a wrench mark for Technician, a gear for Engineer, a flask for Scientist, a headset for Controller) shown next to its pool count, instead of a bare number — adds visual texture without violating the no-character-illustration rule (§1b).
3. **Research tab — v1.2 redesign, own top-level tab (§2g), replaces the v1.1 compact-tree-in-Campus attempt, which the owner still found unsatisfying.** Two directions were considered:

   **Design A — "Orbit map" (radial):** the 4 branches emanate as arms from a central hub, node circles connected by lines, laid out like a star chart — strongly on-theme visually, but a nonlinear radial layout resists collapsing to a narrow mobile viewport and is harder to scan top-to-bottom quickly.

   **Design B — "Timeline lanes" (horizontal, SELECTED):** each of the 4 branches is its own horizontal, independently-scrollable lane — a compact row of small connected node icons, current/available/locked/done by fill, all 4 lanes stacked vertically so the ENTIRE tree fits in view without opening anything. Left-to-right reads as "progress over time," which matches the idle-game mental model directly, and horizontal-scroll-per-row is a well-understood mobile pattern (unlike radial layouts). Tapping a node opens the same detail sheet/panel as v1.1 (cost, duration, effect, Start button) — the interaction model that already worked is kept, only the spatial layout changes.

   Rationale for B over A: mobile-first requirement (UI_SPEC §5) decides it — a horizontal lane degrades gracefully to a narrow screen, a radial hub does not. One active node — its timer shows in the tab header AND in the process strip (§2c).
4. **Launch Sequence screen** (own full screen, entered from Launch tab when a mission is staged; one instance per pad once Pad B exists, with a pad selector header): mission header, 8-item checklist with real-time states (done ✓ green / active with spinner+timer / pending grey), **Confidence Dial** (replaces the plain-percentage display — a radial gauge/instrument, blueprint-style needle sweeping to the current Confidence value on a 0–100 arc; each formula term (base, certification, staffing, weather, XP bonus) renders as its own colored arc segment, filling in as that term is satisfied, so the dial visually builds toward 100% the same way the checklist does — tap still opens the numeric breakdown, the dial is the primary read, not a replacement for the detail), dominant full-width COUNTDOWN button (disabled until checklist complete; the single largest interactive element in the game), Mission Log strip at the bottom narrating live. **Progressive rocket blueprint assembly (new — a "something real to look at" gap versus text-and-timers-only):** during VAB integration, the rocket's blueprint SVG (§1b) builds up visually as each of Aurora I's 5 stages completes — an empty outline at start, filling in Structure, then Engines, then Guidance, then the payload, then final integration — instead of a static blueprint that only appears once, finished, at the end. Reuses the already-planned blueprint art technique; no new art pipeline needed, just staged reveal of the same SVG's layers tied to stage completion. Applies to Aurora II's integration too once it exists. **Weather radar sweep (Visual Identity 2.0, cheap win):** the "optimal weather window" checklist item shows a small animated radar-sweep (a rotating line on a circular scope, blueprint style) instead of a bare countdown — the same information, with a scan-for-a-signal feel that fits a launch-weather wait better than a plain timer.
5. **Countdown & result** — full-screen takeover: 10→0 with narrative feed, then result card (success/failure), rewards breakdown (XP, Reputation, Flight Data, Records unlocked), next-objective teaser. **Applies identically to S-1/S-2 sonda flights, not just Aurora I** — a real gap found in play: the sonda mini-checklist flow was ending in a Mission Log line the player could easily miss (§2f), with no result takeover and no explanation of what a flight is even for. Fix: sondas get the SAME full-screen countdown+result treatment as Aurora I, scaled to their shorter mission (no need to shrink the moment, just the checklist above it). **The sonda's mini-checklist screen also gains a one-line purpose blurb above the checklist** (NARRATIVE §9, new entries) — stating in plain language why the player is launching this and what they get, since "why am I doing this" was unclear from the checklist alone.
6. **"While you were away"** — modal on open when >5 min elapsed: per-resource gains, processes completed, anything now ready, **and any payroll-stoppage window (start, duration, what was paused)**.
7. **Contracts panel** (appears with the Launch Rail for tier-0 offers; expands with satellite tiers post-Aurora I): offer cards (client, requirements with have/need coloring — including tier badges for Titanium requirements, deadline, pay), active contract with its build/queue status, pad queue visualization (who holds each pad — including Pad B once built).
8. **v1 milestone screen (Sprint 10 task 3, NEW — this is a chapter-close, NOT a game-over):** fires once, on the FIRST successful Aurora II launch — the same moment N-16's beat fires. Full-screen, dismissible, never shows again after. Content: a compact run summary (total launches by type, Program Records earned, elapsed play time, total Funding raised), N-16's narrative text, and a one-line crewed-mission teaser (GDD §13's post-launch roadmap — astronauts, Moon, station, Mars — phrased as "what's next for the program," not a literal in-game unlock). **Framing matters: the game does NOT end or lock here** — contracts, further XP nodes, and repeat launches remain fully playable, matching GDD §0's "no reset prestige, long finite arc" pillar. Copy must read as "you reached orbit — here's the story so far and what could come next," never as an ending screen in the closing-credits sense. Dismiss returns to the normal dashboard.

## 4. States & feedback rules
- **A capped resource always names what raises the cap.** When a resource sits at/near its cap, the ticker's amber warning is tappable and states the specific building/upgrade that raises it (e.g. "Build a Warehouse to raise this cap") — leveling an unrelated building (a common confusion: Finance does not raise the Funding cap, Warehouse does) must never be the only clue.
- **Every consuming building shows its inputs, not just its output.** Fabrication/Refinery-type tiles show a "Consumes: 2 Materials per Hardware" line beside their production line — production without cost is only half the picture.
- **Upgrade buttons preview the NEXT level's delta**, not just the current effect: "Level 16 → +2 Funding/s (currently +30/s)". Answers "why upgrade" at a glance, every level, forever.
- **A node/upgrade with no mechanical effect says so explicitly** — "No other effect — unlocks Titanium research" — never silence. Silence reads as broken, not as "nothing to report."
- **Tier changes get a one-time confirmation.** The instant a new Hardware tier is researched, the ticker's Hardware row becomes tier-aware (breakdown visible) and a one-time toast fires (NARRATIVE §8, T-14) — otherwise "nothing happened" is the correct-but-illegible truth (new Hardware now accrues to the new tier, but nothing may consume it yet).
- **Promotion surfaces its own economic case when it's true.** Hiring cost scales `1.15^hiredOfThatRole` per role while promotion cost is flat — so at higher headcounts, promoting is objectively cheaper than hiring. When that's currently true for a role, the staff panel shows a small hint: "Promoting is cheaper than hiring right now." No value changes — this is surfacing an incentive the numbers already contain, not adding one.
- **Upgrade buttons preview the NEXT level's delta ONLY** — "Level 16 → +2 Funding/s". Drop the redundant "(currently X/s)" — the tile's own production line right above the button already shows the current rate; repeating it in the button is clutter, not clarity.
- **"Fully staffed" copy is dynamic, not generic:** if a slot-adding upgrade exists for that building and isn't bought yet, name it — "Fully staffed. Buy 'Grants desk' to add another slot." If no such upgrade exists for that building, say "Fully staffed. This building's slots are fixed — level up to raise output instead." Never the old flat "raise the building's level" line when it's factually wrong (leveling does NOT add slots).
- **Rate precision must never round a real, nonzero delta down to 0.0.** The real bug: R&D Lab's 0.03 Research/s per level rounds to "+0.0/s" at the standard 1-decimal rule, reading as broken. Fix: any rate/delta below 0.1 in magnitude renders with 2 decimals ("+0.03/s") instead of the usual 1; values ≥ 0.1 keep 1 decimal as before. Audit every rate display for this — R&D Lab is the known case, but check Fabrication (0.3/level) and Refinery (0.5/level) too since they're close to the boundary.
- **Every consuming building shows its inputs, not just its output.** Fabrication/Refinery-type tiles show a "Consumes: 2 Materials per Hardware" line beside their production line — production without cost is only half the picture.
- **Nothing purchasable is offered without stating its effect.** Every building, upgrade and hire shows plain-language copy (NARRATIVE §6) describing what it does, visible BEFORE purchase — on the button, its tooltip, or the tile. A name and a price alone is a spec violation. Items not implemented in v1 (`[v2]` in ECONOMY §4) are not rendered at all — not greyed, not teased. **Scope: this rule covers player CHOICES (upgrades, buildings, hires) — never a scripted narrative outcome.** Probe-1's first certification test (GDD §7, the designed first failure) shows its cost and duration like any process, but never a result or a Confidence percentage — there is nothing to disclose because the player isn't choosing an outcome, and no Confidence formula applies to that individual test (§7b's formula describes the certification as a whole). The surprise is preserved by omission of a result, not by omission of cost.
- **Idle-hire warning is short; per-role salary is always visible instead of buried in a paragraph.** T-11's old full-sentence warning is replaced by a terse inline flag ("Idle — still costs salary") next to the hire button when no slot is open. In its place, the hire panel shows each role's ongoing cost permanently: "Hire Technician ($50) — 0.15 Funds/s", not just an aggregate "Salary burn" total. The player should see the recurring cost of a decision at the moment they make it, every time, not just when it's a mistake.
- **Idle staff must never be a silent trap:** the hiring panel always shows total open slots across the program (T-10); hiring with zero open slots requires acknowledging that the hire will be idle and still paid (T-11); a fully-staffed building explains that slots are fixed and levelling is the way to grow output (T-12). Hiring is never blocked — the player keeps the choice, informed.
- **Cost & amount rendering (systemic rule — replaces the old "no single-letter abbreviations" rule, which treated only the symptom):**
  - **Costs and price tags render as icon + number, with NO resource noun**: `[⚡] 400 · [🔧] 30`. Reading "400 Funding" or "30 Hardware" as a price is the bug — prices carry units, not internal data names.
  - **Funds use the currency symbol `$` as a prefix and no noun at all**: `$400`, `$1.25M`. This is the only resource with a symbol instead of an icon.
  - **Full resource names appear only in the ticker, tooltips, the staff/economy panels, and reward summaries** — places where the player is reading *about* a resource rather than paying with it.
  - Doc-internal shorthand (F/M/H/P) never appears in player-facing UI, ever.
  - Every icon has a tooltip/long-press with the resource's full name — icons alone must never be the only identification.
- **Manual-action cooldowns are always visible and acknowledged:** the button shows a recharge animation (radial or fill) for the cooldown duration, and a click landing during cooldown gives immediate feedback (subtle shake/flash) — a cooldown must read as rhythm, never as a dead button.
- Every affordable action is visually distinct the moment it becomes affordable (border pulse once, then steady highlight).
- Every timer shows remaining time in human units (2h 14m, 45s).
- Every resource deduction/gain animates from the triggering element toward the ticker.
- Milestones: small non-blocking call-out card (title + one Mission Log line), auto-dismisses.
- **Payroll unpaid (GDD §1b):** persistent red "PAYROLL UNPAID" chip in the ticker; every paused staffed building shows a pause icon + "awaiting payroll" microcopy; the chip taps through to the Staff panel. Tooltip T-07 fires the first time. Color is never the only signal (icon + text).
- Confidence <100 at countdown: button shows "Launch at 87%" and requires a confirm tap with the risk stated plainly. No hidden odds, ever. The odds shown are the true committed odds (roll drawn at checklist completion, GDD §7b).
- Empty/locked states always state the unlock condition — never a bare padlock.

## 4c. Manual verbs recede when low-value (real finding, presentation only)
Real finding: Pitch/Gather Materials/Rush Order stop being clicked once passive income dwarfs them, but stay pinned at full visual prominence forever, cluttering screens the player has outgrown. **Decision: keep the verbs — removing them removes real, if rare, value** (Rush Order matters exactly in a genuine Materials pinch, and ECONOMY §3b's friction work is specifically meant to create more of those moments). The actual fix is presentation: a manual verb whose single use is currently worth less than ~1% of the player's passive income in that resource visually recedes — smaller, moved into a collapsed "Manual actions" drawer rather than commanding primary screen space — and expands back to full prominence the moment it becomes relevant again (e.g. a real Materials shortage). Never fully hidden, never disabled — just de-emphasized by relevance, the same underlying principle as progressive disclosure applied in reverse.

## 4b. Staff dismissal (new capability)
The staff panel gains a "Release" action per pool member (unassign first if assigned). No refund of hiring cost — that's the real cost of a hiring mistake, same philosophy as insolvency being self-inflicted-but-recoverable. Salary stops the instant of release; the slot they occupied frees immediately. Confirm-on-click (single tap + inline confirm, not a modal) since it's reversible in spirit (re-hiring is always possible) but irreversible in save state.

## 5. Responsive rules
Desktop (≥1024): sidebar nav, tiles in 2–3 columns, Log docked. Mobile (<768): tab bar, single-column tiles, Log as bottom sheet, Launch screen unchanged (it is already mobile-shaped). Touch targets ≥44 px. The Android wrap (post-launch) reuses the mobile layout as-is.

## 6. Settings screen (v1 — required, not optional)
Accessed from a gear icon in the ticker. Contains: **save export/import** (copy-paste string AND download/upload file — localStorage is fragile and save loss is the #1 killer of long idle games; this ships in v1, not later), manual save button + last-saved timestamp, hard reset (double confirm), sound on/off, reduced motion toggle, number notation (suffix/scientific), **telemetry opt-in checkbox (Sprint 12; plainly worded, off by default)**. Export string is versioned and validated on import with a clear error for corrupt/newer-version saves. (Note: import restores the committed launch roll along with everything else — saves are deterministic snapshots.)

## 7. Accessibility
Contrast AA minimum on all text; color never the only signal (icons + text accompany green/amber/red states); reduced-motion setting disables rolling numbers and pulses; font scaling respected.
