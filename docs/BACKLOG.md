# BACKLOG.md — Aurora Program — v2+ ideas (documented, NOT for v1)
*Ideas parked by explicit decision. Nothing here enters code until v1 ships and playtest data informs prioritization. Adding to this file is always allowed; promoting an item to the GDD requires updating the GDD first.*

## Committed for v2 (owner decision, 2026-07)
- **Rocket configuration (KSP-lite):** choose engine + tank + payload instead of fixed recipes. Multiplies balance surface; natural fit when the crewed era needs vehicle variety. Interacts with Confidence formula — design that interaction before building.
- **Dynamic weather with forecast:** weather window shows a mini-forecast ("optimal in 2h, acceptable in 20 min") with a Confidence trade-off for launching in acceptable-but-not-optimal conditions. Builds on the existing Weather Station upgrade.
- **Achievements (platform + in-game):** on top of the Program Records system — Records are the in-fiction layer, achievements the meta layer.
- **Detailed historical statistics:** per-launch archive (payload, confidence, outcome, date), program graphs over time. Pairs beautifully with the Mission Log.
- **Additional launch pads (3rd+):** the program keeps growing — each new pad raises parallel mission capacity. (The 2nd pad is already in v1; the schema is per-pad, so a 3rd pad is a data addition, not a migration.)

## Parked for the Sprint 8 economy unlock (specified, NOT implemented before then)
**Campus & Production internal upgrades.** Rationale: Testing and Launch have 9 internal upgrades between them; Campus has 2 and Production has 0 — the complexes the player lives in for the first hours are the emptiest. Slot-adding upgrades additionally solve the idle-staff problem (see below) by making headcount growth a bought, priced decision instead of an automatic one. Every item must pass the depth rule: it should change a decision, not just a number. **Values below are provisional — Sprint 8 must price them and re-run the sim sweep (salary band 30–55%, Flight Data 20–35%, pacing floor day 5 / ceiling day 12).**

| Building | Upgrade | Effect |
|---|---|---|
| Finance | Grants desk | +1 Technician slot |
| R&D Lab | Technical archive | +1 Scientist slot |
| R&D Lab | Second research track | **Two research nodes run in parallel** (mechanic change — the depth item of this set). **Repriced (owner direction, Sprint 11.5): minimum 10,000 Funding + a real Materials cost, meant to take genuine time to reach — this is the set's marquee item and should feel earned, not an early buy.** |
| Supply Depot | Bulk contracts | +1 Technician slot |
| Refinery | Recovery loop | −10% Materials consumed per Propellant |
| Fabrication | QA station | −15% Materials consumed per Hardware |
| Warehouse | Inventory system | +25% to the cap bonus each Warehouse level grants |

**Slots-per-level (considered, REJECTED):** growing slots automatically with building level was rejected — it converts every level-up into mandatory extra headcount, and salaries already sit at the top of the band (53–55%). Bought slot upgrades give the same relief with full balance control. Also rejected: blocking hires at the slot ceiling (kills agency, breaks hiring ahead of construction, and idle staff are legitimate promotion feedstock) and giving idle staff a passive bonus (would make the assignment decision meaningless).

## Other parked ideas

## Independent analysis — fresh proposals (not from either audit, Claude's own review)
- **A real mutually-exclusive research choice, not just parallel branches.** The "illusion of choice" complaint (already tracked) is usually solved with more parallel paths — but a genuinely more interesting fix is a single node where researching ONE option permanently locks out another, forcing a playstyle identity rather than just a sequencing preference. Candidate: an early Propulsion fork — "Aggressive fuel mixture" (higher Confidence ceiling, cheaper Propellant, but a harsher failure penalty) vs. "Safety-margin mixture" (lower ceiling, costs more Propellant, gentler failure) — both permanent for the save. This is a small, cheap node (no new systems) that does more for "meaningful choice" than adding another parallel path would, because it can never be undone or picked around.
- **Client satellites visible on the Constellation View, distinctly colored from the player's own.** Directly answers the "recurring contract clients have no felt continuity" gap using a system that already exists (Visual Identity 2.0's Constellation View) instead of writing new narrative content — a LinkSphere/OrbitNet satellite appearing on the same view your own Aurora missions populate makes "you're building out someone else's constellation too" visible for free. Cheap: it's the same dot-on-a-ring primitive, just tagged by client instead of only by mission type.
- **Post-Aurora-II self-imposed challenge toggles ("Director's Cut" modifiers), for replay value instead of more grind.** If the dual audit's finding holds up in the cold playtest (content genuinely runs out mid-arc), the instinct will be "add more stuff to climb" — but a cheaper, different answer is to make what's ALREADY there worth replaying: once Aurora II is reached, unlock a small set of optional flags (no scripted-failure safety net, tighter contract deadlines, no offline-cap research) that don't add content but change how the existing content plays. Pure flags, no new balance surface, and it reframes "the game is short" as "the game has a normal mode and a hard mode" rather than "there wasn't enough content." Worth weighing against BACKLOG's heavier options (Program Policies, deeper trees) as a much cheaper alternative if the cold playtest says depth is the issue but budget/time is tight.
- **Organization/Prestige Flight XP trees lack a mechanic-changing node — GDD §9 violation, found by audit.** GDD §9 states every XP tree has ≥1 node that changes a mechanic, not just a percentage; Propulsion (Partial reusability) and Operations (Parallel integration) comply, Organization (Team culture, Recruiting) and Prestige (Public relations, Trusted brand) don't — both are 2-node pure-percentage trees. Same pattern already precedented by Aluminum alloys getting a real effect. Candidate for a post-cold-playtest content pass if the arc needs the depth (see ECONOMY §3e — deferred pending playtest data, not built now).
- **Recurring contract clients (LinkSphere/OrbitNet) have no escalating narrative tied to the relationship** — a modest gap against GDD §6's own stated mitigation for the KSP grindy-contracts failure mode ("constellation clients giving multi-launch continuity"). Flagged as uncertain value by audit, not decided. One fresh angle worth considering later: the Constellation View (Visual Identity 2.0) already tracks every launched satellite visually — client satellites color-coded distinctly on that same view would make "your relationship with a client" visible for free, reusing an existing system instead of writing new narrative content.
- **Sim's undisclosed Controller-staffing simplification:** `sim/run.ts`'s Aurora-readiness check only verifies Launch Control is built, never that it's staffed with Controllers (the real game correctly requires both). Every other simplification in the file's header is explicitly disclosed; this one isn't, and it measurably inflates the `optimal` profile (0 controllers hired across 30 days, still reports Aurora I day 2 and 112 contracts — unachievable under real rules). Doesn't affect human-profile targets. Fix the sim's model OR at minimum document it as a known simplification — pick one before trusting `optimal` as a genuine upper bound again.
- **Milestone-callout positioning is layout-fragile:** currently a hardcoded `position:fixed; top:` pixel offset that breaks whenever the ticker's height or Current Directive's text length changes (both do, by design). Needs JS-measured positioning or a flow-relative layout, not another guessed constant — flagged explicitly rather than re-patched with a third hardcoded number.
- **Real produced audio (post-v1):** v1 ships with Web Audio API-synthesized tones only (UI_SPEC §1c) — no licensing/sourcing questions, matches the code-only art philosophy. Real sound files/music are a possible post-launch upgrade if the owner ever wants to commission or license them; needs an explicit source, not something an assistant fetches unprompted.
- **Research branch parallelism ("illusion of choice"):** genre research (r/incremental_games-adjacent dev feedback, multiple itch.io comment threads) repeatedly flags overly-linear research trees as a weakness — players want SOME branching even early, not one strict chain per branch. Aurora Program's Program branch in particular is 100% linear (Basic engineering→Scientific method→Test stand→Flight operations→Flight program→Orbital flight, each strictly gating the next). Not urgent for v1 (real fix needs redesigning dependencies + a sim re-run, and the 4-branch structure already gives SOME parallelism — the player picks which branch to work on). Worth a look during Sprint 11's dedicated balance pass: could 1-2 branches offer a real fork (two nodes at the same tier, pick one first) without expanding scope much?
- **Resource-flow animation (Materials→Hardware, etc.):** proposed alongside Visual Identity 2.0's four selected features (Confidence Dial, Constellation View, Program Site Map, Building Pictograms) but not chosen this round — a small animated dot/particle flowing from producer to consumer icon on each production tick. Cheap, low-risk, revisit anytime; the four selected features were judged higher-impact for this pass.
- **"Signal burst" rare clickable bonus event (space-themed, e.g. a meteor shower or deep-space signal crossing the screen, click for a short burst reward):** proposed alongside the Current Directive/Confidence-explainer additions but not chosen this round — the owner picked the other two. Extra validation found in genre research: several devs/players explicitly noted a trend toward "more active" incrementals (rewarding brief engaged check-ins, not just pure idle) as something the genre has been moving toward and enjoying. Still a real scope item (touches rewards, needs its own design + economy unlock) — revisit if Sprint 12 playtesting suggests the game feels too passive/needs a reason to glance back at the screen.
- **Resource-production research perks (rate/output multipliers via tech):** the owner asked whether research could unlock more raw production perks (beyond unlocking buildings/mechanics) — a fair idea, and it directly addresses the design review's earlier-flagged concern about thin post-Aurora content. Candidate nodes: Materials/Hardware/Propellant output multipliers, deeper in each branch past the current v1 endpoints. Needs its own design pass and economy unlock; do not add ad hoc.
- **Hiring-cost curve steeper (base cost and/or the 1.15^hiredOfThatRole factor):** owner's instinct, playing manually, is that hiring stays too cheap for a program that will never have thousands of staff. Agreed as worth revisiting, NOT changed in Sprint 9.5 — real balance work needs a sim sweep, not a guess. **Scheduled: a dedicated balance-pass sprint right before the itch.io build** (whenever that final sprint is planned), alongside a general fresh look at the whole economy with 10 sprints of accumulated content behind it.
- **Player-facing speed control (beyond the dev-only time-warp):** an official "fast forward" toggle for real players is a separate, later question from the owner's own ×5 dev-testing convenience (SPRINTS Sprint 2). Not decided; revisit post-playtest if testers ask for it.
- **"Launch early" as a real skippable checklist action:** GDD §7b's "0 if launched early" wording was clarified (v2.10) as describing the live Confidence preview only — in v1, weather and controllers are mandatory checklist items like the other 6, no skip exists. A genuine skip action (proceed without the optimal weather window, or with controllers short-staffed) is a real strategic tradeoff worth building, but only once Sprint 9's contract deadlines create actual time pressure to make it meaningful. Needs its own design pass (when is skipping tempting vs. reckless?) and an explicit economy unlock — not a byproduct of a checklist clarification.
- **Give "Aluminum alloys" a real effect — CONTINGENCY MET.** The owner's first manual playthrough independently flagged the Materials branch as thin (2 nodes vs Program's 6) and asked for more to research. This is the exact signal this item was waiting for. Promoted to the Sprint 8 economy-unlock work list (SPRINTS.md) alongside the Campus/Production upgrade set below — small Fabrication bonus on Aluminum alloys, priced and sim-verified together.
- **Contingent FTUE fix — manual Research verb ("Field observations"):** a small manual action granting trickle Research before the R&D Lab is staffable, to soften the day-1 bootstrap gap the simulator flagged (Research sits at 0 for most of day 1 while the promotion chain runs; ~12h stall on `basicEngineering`, all seeds). Activate ONLY if Sprint 8 testers report day 1 feeling dead — the stall is currently accepted as intended Kittens-style pacing, and day 1 is otherwise full (building, pitching, hiring). If activated, it follows the evolving-verb pattern of pitch/gather.
- **Rival space agency:** a competitor racing your milestones (space-race fantasy). Full parallel-simulation system — major expansion material. The Mission Log can *hint* at rivals with text long before simulating one.
- **Program Policies** ⟨KSP Administration⟩: active policy slots trading income types.
- **Booster recovery:** extension of the Partial Reusability XP node into a per-launch mechanic.
- **Staff names/portraits for role pools:** flavor only; deliberately reserved so individual identity stays special for astronauts (era 2).
- **Offline cap beyond 16 h:** further Remote Ops tiers (24 h+) as late-game research/Funding sinks — v1 stops at 16 h (Remote Ops node, now in ECONOMY §5).
- **Visual themes / light mode, cloud save, i18n beyond English.**
